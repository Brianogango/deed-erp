1. What this API provides

The Partner API is a read-only catalog API for approved resellers. It returns active, priced products with live stock availability so you can list Deed Technologies products on your own storefront.

IncludedNever included
Name, SKU, barcode, description, category, condition (productType) Cost / purchase prices
Retail selling price (KES), warranty months Supplier details, internal accounts
Live quantity available / in-stock flag Order placement (contact Deed commercially)

2. Getting your API key

Keys are created by Deed staff (director or admin officer):

  1. Sign in to Deed ERP.
  2. Open Settings → Partner API.
  3. Click New Partner Key and enter a clear partner/site name.
  4. Click Create Key.
  5. Copy the key immediately — it is shown only once.
  6. Share it with the partner over a secure channel (password manager, encrypted email).
Shown once The full key looks like deed_pk_…. If it is lost, revoke the old key and create a new one. Revocation is immediate.

3. Storing and using the key safely

Treat the API key like a password.

Do

  • Store it in a server environment variable (e.g. DEED_PARTNER_API_KEY).
  • Call this API only from your backend.
  • Use one key per site/integration.
  • Rotate the key if it may have leaked.

Do not

  • Embed the key in browser JavaScript, mobile apps, or public repos.
  • Commit .env files that contain the key.
  • Share one key across unrelated partners.
  • Log the full key in application logs.
Recommended pattern Browser / mobile app → Your backend (key lives here) → Deed Partner API

4. Base URL and authentication

Base URL: https://<your-deed-erp-host>

Send the key on every request with either header:

Authorization: Bearer deed_pk_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX

# or

X-API-Key: deed_pk_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX

Prefer Authorization: Bearer unless your stack makes custom headers awkward.

7. Implementation walkthrough

  1. Store the key in server secrets: 
    DEED_ERP_BASE_URL=https://<deed-erp-host>
DEED_PARTNER_API_KEY=deed_pk_your_real_key_here
  2. Fetch from your backend — walk pages until page >= totalPages.
  3. Upsert into your CMS/DB by id or sku.
  4. Render from your cache/DB; hide or mark out-of-stock items.
  5. Refresh every few minutes (5–15 is typical). On 429, honour Retry-After.
  6. Rotate by installing a new env key if Deed revokes the old one (401).

8. Sample code

Node.js — fetch all pages

const BASE = process.env.DEED_ERP_BASE_URL
const KEY = process.env.DEED_PARTNER_API_KEY

async function fetchCatalog() {
  const items = []
  let page = 1
  let totalPages = 1

  while (page <= totalPages) {
    const url = new URL('/api/public/v1/products', BASE)
    url.searchParams.set('page', String(page))
    url.searchParams.set('pageSize', '100')

    const res = await fetch(url, {
      headers: { Authorization: `Bearer ${KEY}`, Accept: 'application/json' },
    })

    if (res.status === 429) {
      const retryAfter = Number(res.headers.get('Retry-After') || 60)
      await new Promise(r => setTimeout(r, retryAfter * 1000))
      continue
    }
    if (!res.ok) throw new Error(`Deed API ${res.status}: ${await res.text()}`)

    const data = await res.json()
    items.push(...data.items)
    totalPages = data.pagination.totalPages
    page += 1
  }
  return items
}

Python

import os, time, requests

BASE = os.environ["DEED_ERP_BASE_URL"].rstrip("/")
KEY = os.environ["DEED_PARTNER_API_KEY"]
HEADERS = {"Authorization": f"Bearer {KEY}", "Accept": "application/json"}

def fetch_catalog():
    items, page, total_pages = [], 1, 1
    while page <= total_pages:
        r = requests.get(f"{BASE}/api/public/v1/products",
                         headers=HEADERS, params={"page": page, "pageSize": 100}, timeout=30)
        if r.status_code == 429:
            time.sleep(int(r.headers.get("Retry-After", "60"))); continue
        r.raise_for_status()
        data = r.json()
        items.extend(data["items"])
        total_pages = data["pagination"]["totalPages"]
        page += 1
    return items

9. Pagination, caching, and rate limits

  • Use pageSize=100 for sync jobs; read pagination.totalPages.
  • Cache on your side for at least 60 seconds (server responses may also cache for up to 60s).
  • Rate limit: 120 requests/minute per key. Exceeding returns HTTP 429 with Retry-After.
  • Rate-limit headers: X-RateLimit-Remaining, X-RateLimit-Reset.

11. Go-live checklist

  • Unique deed_pk_… key for this site only
  • Key in server secrets — never in the browser
  • cURL smoke test returns JSON products
  • Backend syncs all pages
  • Storefront shows KES prices and stock status
  • Cache ≥ 60s; sync job is not hammering the API
  • 401 / 429 handling in place
  • Deed contact known for key rotation and orders
